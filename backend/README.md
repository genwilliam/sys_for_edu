## 数据库配置（Database setup）

后端使用 Spring JDBC 和 Flyway 进行数据库迁移。生产环境默认使用本地 MySQL 数据库：

```
URL:      jdbc:mysql://localhost:3306/sys_for_edu?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
用户名:    root
密码:      （空）
```

启动后端之前，需要先创建 `sys_for_edu` 数据库；也可以通过以下环境变量覆盖数据库连接配置：

- `DB_URL`：数据库连接地址
- `DB_USERNAME`：数据库用户名
- `DB_PASSWORD`：数据库密码

应用启动时，Flyway 会自动执行位于 `src/main/resources/db/migration` 目录下的数据库迁移脚本。

测试环境使用 `test` 配置文件，采用启用了 MySQL 兼容模式的内存数据库 H2，并执行相同的 Flyway 数据库迁移脚本。

## 账号与权限

本地演示账号：`admin / Admin@123`、`teacher / Teacher@123`、`student / Student@123`。演示账号登录后无需修改密码。教师/学生自助注册需提供档案编号及数据库中登记的完整手机号；学生账号可立即登录，教师账号需由管理员在“账号审核与请假”页面审核后激活。

管理员拥有全部业务读写权限；教师只能读取本人授课班级与相关学生，并可审核本人授课班级的学生请假；学生仅能读取自己的档案、课表和关联班级，并可提交本人请假。教师请假由管理员审核。服务端 API 会执行角色及数据范围校验，前端菜单限制不作为安全边界。账号密码采用 PBKDF2 哈希，会话使用随机令牌并只保存 SHA-256 哈希。

示例账号凭据是公开的开发环境默认值。部署到公网前必须更换默认账号密码；当前系统没有短信验证码、密码找回或多因素认证，不应把基于登记手机号的自助注册视为高强度身份核验。

## 业务数据 API（Business data API）

除排课外，以下业务域使用统一 CRUD 接口，业务记录由后端校验 ID 并写入 MySQL 的 `business_records` 表：

`campuses`、`teachers`、`students`、`classes`、`courses`、`classrooms`、`attendance`、`orders`、`visits`、`users`、`roles`、`class-memberships`。

| 请求方法 | 接口路径                  | 功能说明                            |
| -------- | ------------------------- | ----------------------------------- |
| `GET`    | `/api/data/{domain}`      | 获取指定业务域的记录                |
| `POST`   | `/api/data/{domain}`      | 新增记录；成功时返回 HTTP `201`     |
| `PUT`    | `/api/data/{domain}/{id}` | 更新指定记录                        |
| `DELETE` | `/api/data/{domain}/{id}` | 删除指定记录；成功时返回 HTTP `204` |

记录以 JSON payload 保存；新建请求可省略 `id`，由服务端生成 UUID。`classes` 的新增/删除会同步创建/删除对应的班级成员记录；班级成员变更会检查班级容量和学生现有课表冲突，并同步更新班级排课中的学生关联；删除学生时会清理班级成员及排课学生关联。未知业务域返回 `404`，不存在的更新/删除记录返回 `404`，重复 ID 或排课冲突返回 `409`。

首次启动时，后端从 `src/main/resources/db/seed/business-data.json` 导入示例数据：10 名教师、185 名学生、6 个班级（每班 30 名成员，容量 32）和 18 条示例排课。只为当前为空的业务域导入完整种子；已有记录不会被覆盖。升级到该版本时，后端会通过一次性种子升级标记补齐缺少的示例教师/学生、保留并合并现有班级成员，并仅插入尚不存在的示例排课；示例班级容量会至少调整为 32，原有非示例记录和其他班级字段保持不变。

## 排课 API（Scheduling API）

所有时间均使用本地时间格式 `HH:mm`。

`weekday`（星期）只能取以下值：

- `周一` 至 `周日`

`type`（课程类型）只能取以下值：

- `常规课`
- `试听课`
- `补课`

`status`（课程状态）只能取以下值：

- `待上课`
- `已上课`
- `已取消`

创建单条排课记录或批量创建时，如果未指定 `status`，默认值为 `待上课`。

### API 接口列表

| 请求方法 | 接口路径                          | 功能说明                                                                                                                                           |
| -------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/schedule-items`             | 获取排课列表；支持以下精确匹配筛选条件：`campus`（校区）、`course`（课程）、`teacher`（教师）、`room`（教室）、`weekday`（星期）、`status`（状态） |
| `POST`   | `/api/schedule-items`             | 创建一条排课记录；成功时返回 HTTP `201`                                                                                                            |
| `PUT`    | `/api/schedule-items/{id}`        | 完整替换指定排课记录                                                                                                                               |
| `PATCH`  | `/api/schedule-items/{id}/cancel` | 取消指定排课记录                                                                                                                                   |
| `POST`   | `/api/schedule-items/batch`       | 原子性批量创建排课记录，请求体格式为 `{ "items": [...] }`；成功时返回 HTTP `201`                                                                   |
| `POST`   | `/api/schedule-items/auto-plan`   | 生成候选排课草案，但不会直接保存                                                                                                                   |

### 排课记录的数据结构

排课记录响应包含以下字段：

- `id`：记录 ID
- `course`：课程名称
- `className`：班级名称
- `teacher`：教师
- `room`：教室
- `campus`：校区
- `weekday`：星期
- `startTime`：开始时间
- `endTime`：结束时间
- `type`：课程类型
- `status`：课程状态
- `studentIds`：参与学生 ID 列表

创建单条排课记录和批量创建时，请求体使用相同的字段，但不包含 `id`。其中 `status` 为可选字段。
`studentIds` 是可选的学生 ID 字符串数组，缺省或 `null` 均按空数组处理；最多 100 个 ID，
每个 ID 必须非空且不超过 255 个字符。服务端会去除首尾空白并去重。更新请求完整替换该排课的学生列表。
排课响应（包括自动排课草案）始终包含 `studentIds`；取消排课保留该列表作为历史快照。

### 自动排课（Auto-plan）

自动排课接口接收以下参数：

- `course`：课程名称
- `className`：班级名称
- `teacher`：教师
- `room`：教室
- `campus`：校区
- `weeklySessions`：每周上课次数
- `durationMinutes`：每节课时长（分钟）
- `weekdays`：允许安排上课的星期
- `startTime`：可安排的最早开始时间
- `endTime`：可安排的最晚结束时间
- `type`：课程类型
- `studentIds`：参与学生 ID 列表（可选，规则同普通排课请求）

接口响应格式固定为：

```
{
  "items": [],
  "complete": true,
  "message": "...",
  "explanation": "..."
}
```

字段说明：

- `items`：生成的排课草案列表，不包含 `id`
- `complete`：是否成功生成完整排课方案
- `message`：结果摘要
- `explanation`：方案说明

完整排课方案的 `message` 格式为 `找到 N/M 节`，其中 N 表示实际找到的课程节数，M 表示目标课程节数。

如果无法生成完整方案：

- `complete` 设置为 `false`
- `items` 中仍可以包含当前已找到的排课草案
- 必须说明这些草案不能保存

只有当 `complete` 为 `true` 时，才能将完整方案提交到批量创建接口 `/api/schedule-items/batch` 进行保存。

批量创建操作会再次检查时间冲突，确保数据一致性。

### 排课冲突规则

当同一星期内的两个时间段发生重叠，并且满足以下任意一项条件时，即判定为排课冲突：

- 教师相同
- 同校区的教室名称相同
- 班级名称相同
- 学生 ID 相同

补充规则：

1. 同名教室仅在同一校区内视为同一资源；不同校区的同名教室可以同时排课。
2. 教师、班级名称和学生 ID 的冲突判断不受校区影响。
3. 已取消的排课记录不再占用教师、教室、班级或学生资源，但会保留学生列表快照。
4. 时间段重叠时，采用上述规则进行冲突检测。

### HTTP 错误响应

| HTTP 状态码 | 含义             |
| ----------- | ---------------- |
| `409`       | 排课冲突         |
| `400`       | 请求参数验证失败 |

参数验证失败时，响应格式为：

```
{
  "status": 400,
  "error": "...",
  "message": "..."
}
```
